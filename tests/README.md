# 検査と検証実験

`リレー走順.html`、`陣取りクイズ.html`・`回答カード.html`、`謎解き脱出.html`・`謎解きカード.html` の計算部分と画面を確かめるスクリプトです。Node.js と Playwright（Chromium）が必要です。

## リレー走順

| ファイル | 内容 |
|---|---|
| `browser.js` | 名簿の貼り付け、ルール、最適な走順、いまの走順の読み込みと入れ替え提案、印刷、自動保存を、架空の33人のクラスで確かめる |
| `browser-edge.js` | 入力の間違い・極端な設定（名簿なし、区間数の不一致、男女未入力、ゾーンが短すぎる、固定区間の矛盾、アンカーだけ長い区間、助走区間など） |
| `robustness.js` | 走りのモデルの前提（後半の落ち方、加速の速さ）や50m走タイムの誤差を変えても、アプリの案がどれだけ良いままか |
| `margin.js` | 走り出しのばらつきに対して、目印を「全組一律」と「組ごと」に近くした場合の比較 |
| `engine.js` | HTML から計算部分だけを取り出して読み込むための補助 |

実行例：

```
node tests/browser.js
node tests/browser-edge.js
node tests/robustness.js
node tests/margin.js
```

名前やタイムはすべて架空です。

## 陣取りクイズ

| ファイル | 内容 |
|---|---|
| `jintori-browser.js` | チーム分け、問題の貼り付け（正解の書き方いろいろ・まちがい・ルーレット／ミッション）、印刷、本番の進行（タイマー・ドラムロール・正解チームのタップ・1問もどす・とばす・最終問題へ・再読み込み後の続き・結果発表）、おたのしみルール（お宝マス・少数正解・3問連続正解・ミッション・ルーレットのラッキー／ハイリスク・実況・順位の▲▼）、保存と読み込み、4:3画面で20チームでもはみ出さないこと、回答カード（チーム選び・表示・文字が画面に収まる・問題が入っていない） |
| `jintori-rules.js` | 陣地の決まり（★本拠地と3マス以下は守られる、1問でうばわれるのは上限まで、空きマスが先、となりのお宝が先、ハイリスクで失うのは1マス、同じ条件なら同じ結果など）を400試合・9,600問で、ボーナスの計算（ダブル・下剋上・少数正解・連続正解）を3,000通りで確かめる。あわせて、おたのしみルールあり・なしで、チーム数・地図の広さごとの対戦シミュレーション（空きマスがなくなる問題、最後の最大・最小マス、15問目の1位が入れかわる割合） |
| `jintori-engine.js` | HTML から陣地の計算部分だけを取り出して読み込むための補助 |

```
node tests/jintori-browser.js
node tests/jintori-rules.js
```


## 謎解き脱出

| ファイル | 内容 |
|---|---|
| `nazo-rules.js` | 6つの謎が1つの答えになるかを、謎の絵や文から計算して確かめる（時計の絵の長いはり・短いはりがさす文字、しりとり、フリック入力、「た」ぬき、社会・大会・会話・会議）。○の文字が「あきらめない」になること、答えの確かめ方（ひらがな・カタカナ・漢字は正解、まちがいや別の謎の答えは不正解）、先生用と生徒用で謎の中身が同じこと、生徒用に答えが書かれていないこと |
| `nazo-browser.js` | 先生用：設定、答えの一覧、謎の紙の印刷（3ページに収まる・答えがのっていない）、本番（お話→ルール→スタート、ヒントが時刻どおりに出る、一時停止、脱出の記録と取り消し、同じタイムは同じ順位、再読み込み後の続き、タイムアップ、＋1分、解説、結果発表）、4:3画面で20チーム・ヒント全部でもはみ出さないこと。タブレット用：チーム選び、スタート、答え合わせ、最後のとびら、脱出成功、開き直し、横向き、記録を消す |
| `nazo-engine.js` | HTML から謎の中身と先生用の答えを取り出して読み込むための補助 |

```
node tests/nazo-rules.js
node tests/nazo-browser.js
```
